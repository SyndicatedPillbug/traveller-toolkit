## Overview

Traveller Toolkit is an Obsidian plugin (v4.0.0) for Traveller TTRPG referees. It provides system-first Traveller tools including UWP generation, subsector management, Traveller Map compatibility, and Dossier Engine v4 non-AI prose generation.

The plugin is a **single-file TypeScript project** bundled with esbuild, designed to run within Obsidian's plugin ecosystem.

## Coding Conventions

### TypeScript

- Target: ES2018
- Module: ESNext
- Strict null checks: enabled
- Module resolution: Node
- No implicit any: disabled (but prefer explicit types)

### Code Style

- **Naming**: camelCase for variables/functions, PascalCase for classes/types, UPPER_SNAKE_CASE for constants
- **Indentation**: 2 spaces
- **Braces**: Opening brace on same line, closing brace on new line
- **Semicolons**: Required (TypeScript default)
- **Line length**: No strict limit, but reasonable

### Patterns

1. **State management**: Direct property assignment on `this.state`, manual UI updates
2. **Event handling**: Inline arrow functions for DOM event listeners
3. **DOM creation**: Uses Obsidian's `createEl()` and `createDiv()` methods
4. **Async operations**: Uses async/await with Obsidian API
5. **Error handling**: Try/catch where appropriate, user notifications via `new Notice()`
6. **UI organization**: Cards with `tt-card` class, rows with `tt-row` class

### Formatting Helpers

- Use `sanitizeFileName(text)` for any user input used in file names
- Use `normalizePath(path)` for cross-platform path handling
- Use `clamp(n, low, high)` to constrain numeric values
- Use `pick(arr, rand)` for random selection
- Use `hx(n)` to convert numbers to hex digits

## Anti-Patterns and Forbidden Changes

### Never Do These

1. **Don't modify generated files**: `main.js` and `main.js.map` are generated by esbuild
2. **Don't modify node_modules/**: Always use npm to manage dependencies
3. **Don't change plugin ID**: `traveller-toolkit` is hardcoded in multiple places
4. **Don't remove type safety**: Keep TypeScript compiler options strict
5. **Don't hardcode paths**: Always use `normalizePath()` for file paths

### Avoid These

1. **Don't modify state without UI updates**: Direct state changes may not refresh the UI
2. **Don't assume hex exists**: Always validate `this.state.hex` before use
3. **Don't assume plugin reference exists**: Check `this.plugin` before accessing
4. **Don't use async without await**: Obsidian API methods are async
5. **Don't overwrite existing notes**: Check for existence before creating files
6. **Don't bypass sanitization**: Always sanitize file names from user input

### Code Quality

1. **Avoid duplicate constants**: Use existing lookup tables (STARPORTS, ATMOSPHERES, etc.)
2. **Avoid magic numbers**: Use named constants or helper functions
3. **Avoid long functions**: Break down complex operations into helper functions
4. **Avoid direct DOM manipulation**: Use Obsidian's DOM creation methods
5. **Avoid global state**: Use class properties and method parameters
